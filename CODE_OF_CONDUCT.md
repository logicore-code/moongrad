# Code of conduct

## The short version

Be decent to each other. This is a small open-source project and it
works best when people feel free to say "I don't understand this
part" and "I think this is wrong" without worrying about how it
lands.

## What is expected

- **Assume the other person is competent and is trying to help.** A
  review comment is about the code, not about the person who wrote it.
- **Argue about the code, not about the author.** "This constant is
  wrong" is useful. "You clearly did not read the docs" is not.
- **Accept that you may be wrong.** Most disagreements in this
  repository are settled by a test — write the test, run it, and let
  the numbers decide.
- **Give credit.** If someone's idea, issue report, or patch led to a
  change, say so in the commit message or the pull request.

## What is not acceptable

- Harassment, personal attacks, or insults of any kind.
- Sexualised language or imagery, and unwelcome sexual attention.
- Publishing someone's private information without their permission.
- Deliberately sabotaging the project, or submitting contributions
  whose purpose is to break the build.

## Scope

This applies to the repository's issues, pull requests, discussions,
and any other space where people take part in the project.

## Reporting

If something happens that should not, report it to the organisers of
the competition through the channel they provided, or open an issue
if it is a code problem. Reports are handled by the project
maintainer.

## Enforcement

The maintainer is responsible for clarifying these standards and for
enforcing them. In practice that means: a comment that violates them
is edited or removed, and a pattern of violations ends a
participation.
